Financial management system (FMC) - Система управления финансами предприятия (СУФП) 

# Краткое описание:

• Backend-сервис для учёта движения денежных средств предприятия

# Основной стек технологий

• Платформа: Java 21

• Фреймворк: Spring Boot 3.x (Spring MVC, Spring Data JPA, Spring Security)

• База данных: PostgreSQL 16

• Безопасность: JWT (JSON Web Token) + Google OAuth2

• Миграция схемы: Liquibase

• Контейнеризация: Docker, Docker Compose

• Тестирование: JUnit 5, Mockito, Testcontainers

• Утилиты: Lombok

# Ролевая модель и безопасность

Система реализует ролевую безопасность на уровне методов (Method-Level Security через @PreAuthorize):

• ADMIN: Полный доступ к управлению пользователями, департаментами и справочниками.

• FINANCE_MANAGER: Создание/утверждение бюджетов, просмотр отчетов по всем подразделениям, управление контрагентами.

• ACCOUNTANT: Создание и редактирование транзакций только внутри своего подразделения. Просмотр бюджета только своего подразделения. Запрещено удалять подтвержденные операции.

• AUDITOR: Доступ «только чтение» ко всем финансовым потокам, бюджетам и системному журналу аудита (audit_logs).

Сценарии аутентификации (Dual-Boot Auth)

1. Локальный (JWT): Логин/пароль. Выдается пара access (короткий срок жизни) и refresh (длинный срок жизни) токенов. Пароли хэшируются строгим алгоритмом BCrypt.
2. Корпоративный (Google OAuth2/OIDC): Вход через корпоративный Google-аккаунт.

# Структура проекта (Package-by-Feature)

Проект представляет собой Maven-приложение, состоящее из следующих модулей:

• 'app' - представлена бизнес-логика и REST API.

• 'StartupLogger' - кастомный Spring Boot Starter, формирующий информацию о среде.


# Профили конфигурации

Приложение поддерживает два независимых профиля без необходимости пересборки артефакта (.jar/образ):
1. test: Используется для запуска Unit-тестов и интеграционного тестирования. База данных поднимается локально/в памяти или через динамические контейнеры Testcontainers.
2. prod: Конфигурация для промышленной эксплуатации. Все чувствительные данные (секреты JWT, ключи Google OAuth2, пароли от PostgreSQL) передаются строго через переменные окружения (Environment Variables). Статическое хранение секретов в файлах репозитория запрещено.

# Кастомный Spring Boot Starter

В проект интегрирован изолированный модуль-стартер. При подключении в classpath он автоматически (через механизм AutoConfiguration / AutoConfiguration.imports) выводит в логи при запуске приложения:

• Активный профиль Spring

• Версию сборки приложения

• Ключевые параметры подключения к БД (без чувствительных данных и паролей)

• Время инициализации контекста

Отключение стартера: При необходимости логирование можно деактивировать в файле application.yml одной строчкой:
yaml
app.startup-logger.enabled: false

# Быстрый запуск через Docker Compose

Для быстрого развертывания требуется установленный Docker.

```bash
git clone <url-репозитория>
cd java-practice-hw
```

2. Выполните сборку и запуск через Docker Compose:

```bash
docker-compose up -d --build 
```

3. Приложение будет доступно по адресу: http://localhost:8080


# Основные API Эндпоинты (v1)

Все эндпоинты имеют префикс /api/v1/ и поддерживают пагинацию (?page=0&size=20&sort=id,desc) для списочных запросов.

• POST /api/v1/auth/login — Аутентификация, выдача пары токенов (Access + Refresh).

• POST /api/v1/transactions — Создание черновика финансовой операции (DRAUGHT).

• PUT /api/v1/transactions/{id}/confirm — Подтверждение транзакции, пессимистический пересчет баланса счетов (CONFIRMED).

• POST /api/v1/transactions/{id}/reverse — Сторнирование подтвержденной транзакции (REVERSED).

• GET /api/v1/budgets/reports/{id} — Получение отчета об исполнении бюджета (План vs Факт).

• GET /api/v1/audit-logs — Просмотр системного журнала аудита (Доступно только AUDITOR и ADMIN).
